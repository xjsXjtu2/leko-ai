## 可复用经验

- **arp-scan 找树莓派的技巧**：别认设备名，认 MAC 前缀。树莓派官方 OUI：B8:27:EB、DC:A6:32、E4:5F:01、D8:3A:DD、2C:CF:67、28:CD:C1、88:A2:9E、98:FE:54（来源：pip.raspberrypi.com RP-003474-WP）。
- Pi 5 绿灯语义：闪烁=读卡正常；完全不闪=没在读卡；规律长短闪=启动失败错误码；常亮=首启后台任务多，属正常。
- Imager 预配 SSH 但 macOS 用裸主机名连不上是高频新手坑，答案永远是 `.local` 或直接 IP。
- 用户随后 ssh 报 No route to host → 实测为首次启动未就绪的暂时现象：几分钟后从本机验证 ping 通、22 端口通、SSH 返回「Permission denied (publickey,password)」（即服务正常等密码）。结论：首启后等几分钟再连即可，无需任何修复。
- **01:14 与 01:20 两次复现短暂掉线（各 <1 分钟），其余时段（01:16–01:19 每4s×45次、01:21–01:26 每2s×150次）全程 UP** → 模式吻合 brcmfmac WiFi 省电导致的 ARP 周期性失联（Pi 上经典问题）。已给修复方案：`sudo iw dev wlan0 set power_save off` + NetworkManager `wifi.powersave = 2` 持久化；备选方案插网线。注意用户反复测 DOWN、我测 UP 的巧合——用户试连时机不巧撞上掉线窗口。

- 接线表行序按用户要求颠倒：现从板角端数起（1B/1A/2B/2A/G/1IN1/1IN2/1P/G/2IN1/2IN2/2P/G），GPIO 映射逐行保持不变（映射跟丝印走，与行序无关）。引脚速查说明同步更新。
- 澄清共地接线：排针 3 颗 G 内部相通，只需接 1 根到树莓派 GND（此前表格 G 行写「—」造成「都不接」误解）；杜邦线总数 11 根 = 共地1+方向4+PWM2+编码器4。同时删除残留的 V8 旧说明（改为 3V 实测流程）。
- 上电顺序定案：先树莓派后电池开关（反序断电），已写入手册第三节；同时删除清单里残留的裸模块「VCC」检查项（集成板无此针）。
